# Frontend

Two static pages. No build step, no bundler, no dependencies: `index.html` loads `app.js` and
`admin.html` loads `admin.js`, both as ES modules over the shared modules in `js/` and eight stylesheets
in cascade order. `serve.py` serves the directory on port 3000 and proxies `/api/*` to `cargo lambda watch` on port 9000,
sending `/api/admin` and `/api/draw` to their own functions exactly as CloudFront does in production.
`config.js` holds the Stripe publishable key and the Cognito client, is generated by `scripts/dev.sh` and
is gitignored; `config.example.js` shows its shape. There is no test runner, so a change is checked by running
`scripts/dev.sh` and opening `http://localhost:3000` and `http://localhost:3000/admin.html`.

The admin console is signed in with Cognito. The page runs the OAuth authorization-code flow with PKCE
against the pool's hosted UI, keeps the access token in `sessionStorage` for that tab only, and sends it
as a Bearer header; `admin` and `draw-run` verify the RS256 signature against the pool's JWKS before they
do anything. Nothing is rendered until `restore()` says there is a live token, but the gate is the
Lambda's check, never the hidden panel. Locally the pool is `cognito-local` in Docker, so the whole
sign-in runs with no AWS account.

## What each module owns

A module owns one job, and nothing else imports its internals.

| Module | Owns |
| --- | --- |
| `js/api.js` | `call`, `form`, `invoke`, `post`, and the `config` import. The only module that calls `fetch`. `invoke` is the one that carries the bearer token. |
| `js/dom.js` | `el`, `show`, `notify`, `sleep`, `element`, `escapeHTML`, `fieldValue`. The only module that looks an element up by id, and the only one that turns a string of markup into a node. |
| `js/format.js` | `at`, `calendarDay`, `day`, `inFieldValue`, `inPounds`, `inWholePounds`, `toInstant`, `toPence`. The only module that converts money or dates. |
| `js/raffle.js` | `renderRaffle`, `renderClosed`, and the public prize list markup. |
| `js/order-form.js` | Reading the form into an order payload, the running totals, submit. |
| `js/journey.js` | The multi-step panel navigation returned as `reveal`. |
| `js/payment.js` | The Stripe client, the payment element, the pay button. |
| `js/confirmation.js` | Polling the order until tickets exist, and the confirmation copy. |
| `app.js` | `boot`: fetch the current raffle, then render open, closed, or returning-from-payment. |
| `js/admin/session.js` | The OAuth dance: PKCE, the redirect out, the code exchange, the token in `sessionStorage`, sign-out. The only module that knows the console has a login. |
| `js/admin/actions.js` | `admin(action, body)` and `runDraw(request)`. The only module that knows an admin call is a tagged `{ action, … }` envelope, which path answers it, and that it carries the token. |
| `js/admin/router.js` | The hash vocabulary: parse `#name/rest`, show and focus one section, light its tab, scope the raffle sub-tabs to the id in the hash, surface a failed route. Returns the one `go(target)` every other module navigates and reloads through, so re-submitting the route already open still re-reads it. |
| `js/admin/task.js` | Running a control's task once: disable it, clear the notice, surface the failure, re-enable it and give it the focus back. |
| `js/admin/markup.js` | The admin row and fact markup, and the cell shapes (`link`, `number`, `state`, `choices`). |
| `js/admin/raffles.js` | The register of every raffle. |
| `js/admin/raffle.js` | One raffle: its counters, the create and update form, and its prize tiers. |
| `js/admin/draw.js` | The draw record, running the draw, the winners and their statuses. |
| `js/admin/ledger.js` | One raffle's ticket ledger, a page at a time, and the only entries cursor. |
| `js/admin/order.js` | One order, reached by its own id or by a ticket number. |
| `js/admin/supporter.js` | The three lookups, the dossier, and erasure. The only surface that renders personal data. |
| `js/admin/subscriptions.js` | Subscribers by status, their cursor, and cancellation. |
| `admin.js` | `boot`: restore the session, then either show the sign-in panel or wire each section against the router's reload. |

Nothing outside `js/admin/` imports a `js/admin/` module, and `app.js` never does.

## JavaScript

- **A function either works out a value or writes to the DOM, never both.** `pollOrderResult` polls the
  API and returns a result object; `showDone` is the only function in that module that writes to the
  page. Split any function that does both before extending it.
- **Async work returns a result object tagged with `status`.** `pollOrderResult` returns
  `{ status: "SUCCESS", tickets }`, `{ status: "FAILED" }` or `{ status: "TIMEOUT" }`, `confirmOrder`
  turns that into `{ message, title }`, and `showDone` writes those two values once. Do not assign to the
  same element inside three branches.
- **A constant's name carries its unit.** `POLL_INTERVAL_MS`, `POLL_TIMEOUT_MS`. A number with no unit in
  its name is a bug waiting to be misread.
- **User-facing copy is a module constant above the functions, never a string literal inside control
  flow.** `FAILED_PAYMENT_MSG`, `PENDING_MSG`, `UNDER_18_MSG`. A sentence used by two messages becomes its
  own constant and is composed into both: `RELOAD_ADVICE` is one sentence appearing in `PENDING_MSG` and
  in the catch branch of `confirmOrder`.
- **One builder per message shape.** `formatTicketMessage` picks the fragment that differs
  (`number is 7` against `numbers are 7 to 9`) and writes the surrounding sentence once. `formatSummary`
  in `payment.js` does the same for the optional donation clause. Never copy a sentence into two branches
  to change three words.
- **Build markup with a template literal and `element` from `dom.js`**, not a run of `createElement`
  and `append`. `prizeItem` is the pattern to copy: destructure the parameter, give each conditional
  fragment a name (`quantityMarkup`), and pass every string that came from the API through `escapeHTML`.
  The escape map is a module constant, not an object literal rebuilt per character. `element` parses
  through a `<template>`, not a range: a detached range drops a `<tr>` or a `<td>` on the floor.
- **A helper stays private to the module that needs it until a second module imports it.** `escapeHTML`
  and `element` were private to `raffle.js` until `js/admin/markup.js` needed them; they moved to
  `dom.js` and both import them. Move, never copy.
- **Money is integer pence in every variable, payload and comparison.** `format.js` owns every `/ 100` and
  `* 100`, through `inPounds` (£25.00), `inWholePounds` (£1,000) and `toPence`. If a new module needs a
  conversion, add it to `format.js`; do not divide by 100 anywhere else. This mirrors the backend rule
  that ticket money and donation money stay separate integers at every layer.
- **Blank lines separate the phases of a function**: what it reads, what it decides, what it writes.
  `renderRaffle` reads and derives in the first paragraph, writes text in the second, and `show("order")`
  stands alone in the third. A closing `show(…)` or `return` always gets its own paragraph.
- **Guard and return early.** `pollOrderResult` returns from inside the loop; `wireJourney`'s click
  handler returns after the `[data-picker]` case rather than nesting the rest in an `else`.
- **Hoist a repeated `el(id)` into a const.** `collectPayment` does `const pay = el("pay")` once instead
  of looking the button up on every line.
- **Predicates read as questions**: `isComplete`, `isOther`. A bare adjective or verb (`complete`) reads
  as neither a question nor a command.
- **`const` arrow for a one-expression helper, `function` for anything longer or exported.** `el`, `show`
  and `inPounds` are arrows; `readOrder`, `prizeItem` and `wireForm` are declarations.
- **Alphabetical**: object literal keys, destructured parameters, named imports inside the braces, and the
  import statements themselves by module path.
- **No comments.** Name the thing instead. This is the same rule the repository root applies to Rust.

## CSS

- **One declaration per line, always.** Never collapse a rule because it only has two properties —
  `.dates` and `.lede` in `01-typography.css` are formatted identically to a twenty-line rule.
- **Properties within a rule are alphabetical**, then nested selectors, then nested at-rules. `.cta` in
  `06-buttons.css` is the full shape: declarations, then `&:active`, `&:disabled`, `&:focus-visible` and
  `&:hover` in alphabetical order, then the `@media` block. Nested `@media` blocks go widest first so the
  narrower one overrides: `h1` in `01-typography.css` nests `max-width: 960px` before `max-width: 600px`.
- **Within a file, element selectors come before class selectors**: `h1`, `h2` before `.eyebrow`, `.lede`.
  A selector anchored by a class files among the classes, not the elements, because the class is what
  scopes it — `.step-head p:last-child` sits with the classes in `04-layout.css`.
- **Component styles are wrapped in `@scope`.** `.picks`, `.prizes`, `.site-header`, `.frame`,
  `.journey` and `.site-footer` each open an `@scope` block, and bare element selectors inside one
  (`li`, `p`, `input`) are scoped by it.
- **Never let a `span`, `div` or `label` stand in anonymously for part of a component — give it a class**
  (`.pick-face`, `.field-text`, `.summary-row`, `.prize-name`). Bare element selectors outside an
  `@scope` block are reserved for the document-wide reset in `04-layout.css` (`*`, `[hidden]`, `body`)
  and the type scale in `01-typography.css` (`h1`, `h2`).
- **A class may exist only to name a part.** `.prize-name` carries no declarations because the `li` grid
  in `03-prizes.css` positions it; the class is still required, so the markup says what the span is.
- **Style with classes, never with ids.** Ids are the JavaScript binding surface — `el("pay")`,
  `el("prizes")`, `el("done-title")` — and no stylesheet contains an id selector. Keep it that way.
- **Visibility is the `hidden` attribute, toggled through `show(id, visible)`.** `[hidden]` is forced to
  `display: none` in `04-layout.css`. Never hide something by setting `display` from JavaScript, and never
  write a `.is-hidden` class.
- **A leaf class that is only a component's caption or face** (`.pick-face`, `.option-text`) may be reused
  by more than one component when the visual spec is genuinely identical. Split them the moment it is not,
  rather than making one class carry two looks.
